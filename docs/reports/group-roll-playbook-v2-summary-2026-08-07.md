# Group Roll 人工手册 v2：易懂总结

## 一句话结论

v2 已经完整做完、可以复现，而且不需要再跑 15 小时；但两份整本手册都没有达到“可靠发布”
标准，所以状态仍是 `draft`。目前最值得直接使用的是 Stat/Quality/Trait 查表；两份 12 条手册
只能作为人工参考，不能当成已经证明的最优策略。

## 这次到底完成了什么

- 两份独立人工手册都已冻结：一份不假设后台生成率，一份使用当前 best-guess 主模型。
- 所有正式 Stat 输入都经过来源门禁：16 个 `exact`、2 个允许的 `derived`，没有 `proxy`，也
  没有把缺失值当成 0。Coach 仍明确排除。
- 完整 40-Roll 验证约 25 分钟；held-out 只读审计 108/108 约 45 分钟。最近一组完整计算合计
  约 1 小时 10 分钟。
- 最长的 108 行审计连续运行两次，得到同一 run ID、语义哈希和文件哈希。
- 没有控制 Dota 客户端、没有自动填写、没有读取未来数据，也没有用 solver 结果偷偷修改手册。

## 两份手册怎么理解

### Primary-model v2

这是两份里证据相对更好的选择，前提是你接受“客户端公开权重的 best guess”作为模型，而不是
真实后台率。

- 好的一面：完整会话里没有超过 10% 的 Common 损失失败；12 条核心规则有 7 条通过消融，
  相比 v1 的 2 条明显增加。
- 不足：另 5 条核心规则没通过；`default-knee` 和 `downside-first` 两个实际生效的风险修正
  都失败；只读审计还发现 `P2M02` 在一个常见的剩余 3 Roll 情形同时劣于直接刷新。
- 实际建议：如果只是探索性使用，优先看 `mean-first` 基线和统一刷新兜底，不要把两个风险修正
  当成已证明能改善下尾。

### Rate-agnostic v2

这份不声称知道后台生成率，原则更容易解释，但本轮整体验证更差。

- 好的一面：只读短视野审计的 81 行跨模型检查没有 10%或方向性重大例外；R2A01、R2A02、
  R2A03、R2A08 四条规则在三个模型下都获得消融支持。
- 不足：完整 40-Roll standalone 有 23 个 Common 情形超过 10% 门槛，96 个超过 5%；只有
  4/12 条在所有 release 模型下通过消融。
- 实际建议：它适合帮助理解“所有合法结果都不降才应用”的保守原则，不适合整本照抄并声称
  与生成率无关就一定安全。

## v2 相比 v1 提升了多少

最确定的提升是工程速度与证据完整性，不是已经证明的大幅得分提升：

- 原始只读审计按旧吞吐曾投影约 7.9 小时；现在完整 108 行约 44–45 分钟，约快 10.6 倍。
- 正常的 standalone + cross-audit 合计约 70 分钟，因此 v2 不需要在 v1 之后再额外运行 15
  小时。第二次 45 分钟 audit 只是本次收口的确定性证明，平时不必重复。
- Primary 获得消融支持的规则从 v1 的 2/12 增到 7/12，但仍没达到 12/12；10% Common
  门槛仍保持为 0 个失败，而不是进一步改善。
- Rate 的跨模型支持规则从 3 条增到 4 条，但整本手册的 10% Common 失败从 v1 的 5 个增到
  v2 的 23 个，属于退步而非提升。
- 预先估计的诚实得分空间本来就只有约小于 1% 均值、0–2.5% 下尾；本轮没有证明 v2 已兑现
  这部分提升。不同 seed 和不同候选的分数不能直接当成因果对比。

## 实际查阅顺序

1. 先看 [v2 Stat、Quality、Trait 表](../playbooks/group-roll/stat-quality-trait-evidence-v2.md)。
   这是当前最扎实的部分，用来判断 keep、conditional-reroll、priority-repair 和精确套装。
2. 如果接受主模型假设，再看
   [Primary-model v2](../playbooks/group-roll/playbook-primary-model-v2.md)；否则看
   [Rate-agnostic v2](../playbooks/group-roll/playbook-rate-agnostic-v2.md)。两者都要连同本报告的
   `draft` 警告理解。
3. 每次只按当前阶段从上到下检查规则；没有规则明确支持当前选项时，使用统一兜底：花 1 次
   Roll 刷新三个共享选项。
4. 在游戏里人工确认真实结果和新选项。不要自动提交，不要用 proxy 补缺失值，也不要把 Group
   手册用于 Main。

两份手册 Markdown 的页首仍保留“P2 候选冻结”字样，因为它们是不可变候选快照，不能在看完
验证结果后回写。当前最终状态以[手册索引](../playbooks/group-roll/README.md)和本总结为准。

## 仍然不能承诺的事

- 不能说任一整本手册已经可靠，更不能说是 40-Roll 全局最优。
- 只读 exact 审计只覆盖剩余 1–3 Roll，未来 offer 使用声明的循环序列，不是完整随机积分。
- 没有新的 v2 full-session P5 solver 验证；历史 v1 P5 失败只用于披露。
- 本地实验顾问仍冻结在 v1 身份，不会自动使用 v2。
- 当前 replay JAR 与历史回填 JAR 的文件 hash 不同；源码未变、两次当前构建一致、6 个真实
  replay 的 300 个值全部通过，但历史 raw 元数据不会因此被改写。
