## 阶段目标、最小范围和验收标准

本阶段有两个目标：把游戏内槽位的全表分配理由改写成人能直接理解的“换座位机会成本”；把支持
五个实力带和关键对位关系的当前版本 Series 结果全部展开，同时诚实显示直接交手缺口。

最小范围只修改 Markdown：两份既有玩家报告、README 入口、一份 Series 玩家版和本技术记录。
不修改 `src/`、测试、模型、配置、规则快照、Forecast artifact 或数据文件，也不重算预测结果。

验收标准为：

1. “联合胜率”不再承担解释；换位示例明确不是两项同时命中的概率；
2. 7.41、合格赛事级别、严格早于 `as_of` 的目标队比赛全部有唯一去向；
3. 每个公开 Series 都满足合法 BO 终局，明细不重不漏，汇总可从明细反算；
4. 无法证明完整的 Game 片段继续供单局模型使用，但不得冒充 Series；
5. 公开版不显示内部队伍 ID、比赛 ID或来源列，并区分与本届队伍同名的其它稳定身份；
6. 既有排名、对位概率和 16 槽填写结果不变；
7. 完整离线测试、格式、依赖、规则、文档链接和 `git diff --check` 通过。

## Series 范围与完整性规则

读取 `data/processed/matches.parquet` 后应用以下固定筛选：

- `patch_name == 7.41`；
- `league_tier` 为 `premium` 或 `professional`；本次命中的行全部为 `professional`；
- `start_time < as_of`，且 `fetched_at <= as_of`、行级 `as_of <= as_of`；
- 系列至少一方是配置中的 16 个稳定目标队 ID。

先在完整 7.41 目录上组 Series，再筛目标队，避免把被截断的对手侧数据误判为完整。常规键为
`(league_id, series_id)`；BO1 单独按稳定 `match_id` 成组。完整性门槛为：

| 赛制 | 合法完整结果 |
| --- | --- |
| BO1 | 恰好 1 局，胜者达到 1 胜 |
| BO2 | 恰好 2 局，允许 2–0 或 1–1 |
| BO3 | 2–3 局，胜者达到 2 胜 |
| BO5 | 3–5 局，胜者达到 3 胜 |

## 结论审查：Series 证据支持到哪里

- Yandex 对追赶组的直接 Series 为 3–0–3、地图 5–5，只支持“绝非稳胜”；56%–58% 的方向来自
  完整共同对手网络；
- 追赶组对胶着中游为 19–1–6、地图 35–17，是跨层判断最强的直接证据；
- Resilience 与 Spirit 无直接完整 Series，胶着中游内部仅 5 个，后段内部仅 3 个；这些细分对位
  必须标为网络推断，不能写成直接交手事实；
- Iron Wing 两次直接击败 Xtreme，而模型仍给 Xtreme 小优，说明窄概率不是 H2H 投票。样本稀少
  时应保留这类冲突，不得为叙事删除。

因此，新玩家版没有声称 Series 账本“证明”精确排名。它把直接支持、证据稀疏和反方向样本同时
展开，支持原报告把主要注意力放在实力带和明显跨层关系。
