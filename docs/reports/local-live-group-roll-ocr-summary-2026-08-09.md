# 本地实时 Roll 识别：易懂总结

日期：2026-08-09
更新：2026-08-10

## 现在能做什么

Windows 本机的 `Group Roll 实时顾问` 现在使用一次性识别按钮。点击后，它会先确认窗口属于
`dota2.exe`，再等待 Dota 所在显示器出现下一张稳定的完整 Roll 页面。随后自动识别三面战旗
的九格内容、眼前的三个 Roll 选项和剩余次数，填进顾问并自动重算“现在选哪个”以及 Title，
然后自动停止。

这里的“自动停止”是指停止截图和 OCR，不是销毁内部线程。程序会保留一个休眠线程，之后每次点击
仍由同一个线程创建和释放 Windows 捕获资源。这样既不会持续监视屏幕，也避免第二次识别时把
WinRT 原生对象换到另一个线程而导致 Python 进程崩溃。

Chrome 和顾问既可以放在另一块屏幕，也可以与 Dota 共用一块屏幕。单屏时先点击按钮，再用
Alt+Tab 切回 Dota 即可。Dota 尚未出现、被最小化或当前不是完整 Roll 页面时，本次请求会继续
等待，不会转而把 Chrome 或其他画面填进表格；等待期间可以随时取消。

识别语言以英文客户端为第一支持目标，同时支持简体中文客户端。两种语言都覆盖角色、Stat、
品质、Trait、三个 Roll 操作和剩余次数；不会依赖中文界面中的英文缩写以外的猜测。

原来的下拉菜单没有删除。不点击识别按钮时就是原始手填版；识别不完整时也可以直接手动修正。
Linux 或托管 Streamlit 只显示手填版。

## 怎么使用

```powershell
uv sync --extra dev --extra ocr
uv run ti web
```

1. 在网页中打开 `Group Roll 实时顾问`。
2. 点击“识别下一次稳定的 Dota 画面”。
3. 切回 Dota，并停留在能同时看到三面战旗和三个选项的完整 Roll 页面。
4. 等画面稳定约两帧；本机 OCR 一次约需六秒。识别完整后会自动填表、自动计算。
5. 在游戏里亲自完成操作。需要读取新页面时，再回到顾问点击一次识别按钮。

## 它什么时候会拒绝自动计算

必须同时确认全部 31 个字段。任何一个 Stat、品质、Trait、Roll 选项或剩余次数读不清，或者
识别出颜色与 Stat 不合法、同一战旗 Stat 重复、三个选项重复，页面都只填入可信字段并列出
缺项，不会拿半张画面生成建议。比赛画面等无关页面也会被直接拒绝。

## 安全边界

它只读取窗口像素并填写本地网页，不会点击 Dota，不会发送键盘输入，不会读取或修改游戏
内存，也不会替玩家提交选择。缓存只保留最新一张目标画面和一份识别 JSON，位于 Git 忽略的
`data/cache/ocr/live-roll/`，不会保存连续截图历史。

## 当前可信度

代码、手填回退、真实比赛画面拒绝、浏览器一次性按钮、等待/取消和线程停止均有回归保护。
单元测试还覆盖了“先最小化、再遇到非目标页、最后出现目标页”的单屏切换顺序。程序化生成的
英文与
简体中文 2560×1440 页面都曾达到 31/31；用户提供的真实 2560×1440 Dota 全屏截图也达到
31/31，并精确还原九格、三个选项和 33 次剩余 Roll。

全屏周围内容不会再直接混入详细识别：程序先找横向对齐的 `CORE / MID / SUPPORT`，再截取并
放大 Fantasy 区域。左侧菜单里的另一个 `SUPPORT`、顶部导航和底部聊天因此不会改变战旗归属。
用户已经确认实际游戏画面能够正确识别并填入。随后发现的“第二次识别卡住并导致 Streamlit
退出”也已定位并修复：两次真实 WinRT 单次捕获现在由同一个休眠工作线程依次完成，OBS 开启时
同样通过。取消旧请求后立即重新开始时，旧 OCR 结果也不能覆盖新请求。
