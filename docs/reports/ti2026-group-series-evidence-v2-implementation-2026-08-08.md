## 阶段前代码和数据审查

阶段开始时 `main`、`origin/main` 均位于 `a3e1762`，工作树干净。现有模型和报告使用同一份
`matches.parquet`，其中 7.41 比赛行只有大版本 `patch_name == 7.41`，没有 7.41a 至 7.41e
字段。数据里有 OpenDota `league_tier`，但没有官方最终名次、轮次或淘汰档字段。

因此不能把新列伪装成原 Forecast 的输入，也不能根据“赛事最后一场”机械推断所有赛事名次。
多名额资格赛尤其没有唯一冠军语义。

## 阶段目标、最小范围和验收标准

阶段目标是把原 7.41 全体赛果扩展成玩家可核对的精确小版本、赛事级别、主赛事最终名次和资格赛
晋级证据，同时保持原 Forecast 完全不变。

最小修改范围：

1. 在 `CONTEXT.md` 增加精确小版本、赛事性质、最终名次档和资格赛结果的互斥术语；
2. 扩展既有玩家版 Markdown；
3. 新增本实施与问题记录；
4. 不修改 `src/`、配置、规则快照、模型、Forecast artifact、Parquet 或随机种子。

验收标准：

1. 871 个目标队 7.41 Game 全部且只落入一个精确小版本；
2. 409 个完整 Series 全部且只落入一个精确小版本，没有跨边界 Series；
3. 六个小版本汇总逐队反算后等于 7.41 全体表；
4. 18 个赛事的 Series、Game、精确版本、赛事级别和性质守恒；
5. 主赛事名次档互斥，资格赛只记录晋级结果；
6. 同名或相似阵容不得绕过稳定队伍身份自动合并；
7. Markdown 链接、发布用语、全量测试和项目级审查通过。

## 已知限制和问题 Memo

1. **精确小版本是发布增强，不是原生比赛字段。** Valve 若修订公告时间，需要发布新报告，不能
   静默改写原 Forecast。
2. **赛事级别无法区分玩家口中的大赛和次级赛。** 当前 18 个赛事全部是 professional；项目没有
   采用来源不统一的 Tier 1/2/3 标签。
3. **名次只跟随稳定队伍身份。** 队名相似、选手转会或赛事页面沿用旧队名，都不会自动回填到
   当前队伍；这会少算一些“同阵容印象”，但避免把不同队伍误并。
4. **资格赛不进入主赛事名次数。** 晋级是独立结果，不能同时算冠军或前四。
5. **5 个不完整 Game 仍不冒充 Series。** 它们进入 871 个单局小版本总数，但不进入 409 个
   Series、逐队 Series 战绩或最终名次反算。
6. **本阶段没有重排实力榜。** 小版本、名次和赛事性质是解释性证据；原综合排名和模型概率保持
   原样，避免赛后挑选一个小样本版本重新拟合结论。
