# 本地实时 Roll 识别：易懂总结

日期：2026-08-09

## 现在能做什么

Windows 本机的 `Group Roll 实时顾问` 多了一个开关。打开后，它会反复查看 Dota 2 窗口；
当完整 Roll 页面稳定下来时，自动识别三面战旗的九格内容、眼前的三个 Roll 选项和剩余次数，
填进顾问并自动重算“现在选哪个”以及 Title。

识别语言以英文客户端为第一支持目标，同时支持简体中文客户端。两种语言都覆盖角色、Stat、
品质、Trait、三个 Roll 操作和剩余次数；不会依赖中文界面中的英文缩写以外的猜测。

原来的下拉菜单没有删除。不开启开关时就是原始手填版；识别不完整时也可以直接手动修正。
Linux 或托管 Streamlit 只显示手填版。

## 怎么使用

```powershell
uv sync --extra dev --extra ocr
uv run ti web
```

1. 在网页中打开 `Group Roll 实时顾问`。
2. 打开“实时监视 Dota 2 的 Group Roll 页面”。
3. 在 Dota 中停留在能同时看到三面战旗和三个选项的完整 Roll 页面。
4. 等画面稳定约两帧；本机 OCR 一次约需六秒。识别完整后会自动填表、自动计算。
5. 在游戏里亲自完成操作。新页面稳定后，顾问会再次识别并更新。

## 它什么时候会拒绝自动计算

必须同时确认全部 31 个字段。任何一个 Stat、品质、Trait、Roll 选项或剩余次数读不清，或者
识别出颜色与 Stat 不合法、同一战旗 Stat 重复、三个选项重复，页面都只填入可信字段并列出
缺项，不会拿半张画面生成建议。比赛画面等无关页面也会被直接拒绝。

## 安全边界

它只读取窗口像素并填写本地网页，不会点击 Dota，不会发送键盘输入，不会读取或修改游戏
内存，也不会替玩家提交选择。缓存只保留最新一张目标画面和一份识别 JSON，位于 Git 忽略的
`data/cache/ocr/live-roll/`，不会保存连续截图历史。

## 当前可信度

代码、手填回退、真实比赛画面拒绝、浏览器开关、线程停止和全项目回归都已通过。程序化生成
的英文与简体中文 2560×1440 完整页面也分别通过真实 OCR 引擎，两次都是 31/31 字段全部识别
成功。

还差最后一项：当前实装期间 Dota 没有停在真实 Roll 页面，所以真实客户端字体和最终排版仍
需用一张实际画面做校准。这个缺口不会让程序偷偷猜值；在完成校准前，建议第一次使用时核对
网页中的九格和三个选项，若有缺项就继续手填。
