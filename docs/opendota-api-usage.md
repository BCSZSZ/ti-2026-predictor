# OpenDota API 使用计划与安全规范

生效日期：2026-08-02。价格与限额依据见
[OpenDota API 价格与限额核查](research/opendota-api-pricing-and-limits.md)。本规范只覆盖当前
`OpenDotaClient` 使用的普通 GET 请求；如果以后加入按多次调用计费的端点，必须先实现对应的
加权记账。

## 预算

OpenDota Premium API 当前价格为每 100 次 `$0.01`，即每次 `$0.0001`。月预算 `$5` 对应：

```text
$5 / $0.0001 = 50,000 次
```

项目把 **50,000 次带 key 的请求尝试/UTC 月**设为不可通过配置抬高的硬上限。环境变量
`OPENDOTA_MONTHLY_REQUEST_LIMIT` 可以将上限调低，但不能设为高于 50,000。只要请求携带 key，
就从第一次请求开始计入本地预算；不能把匿名免费层的 3,000 次视作带 key 请求的免费抵扣。

本地计数采用保守口径：每次真正发出前先记 1 次，重试也计数，且不扣除 OpenDota 账单中可能
排除的状态码。因此本地数字可能高于实际计费调用数，但不会低估当前客户端发出的普通 GET。

## 两级硬停止

| 保护 | 默认值 | 行为 |
|---|---:|---|
| 单次进程上限 | 5,000 次尝试 | 到达后在下一次网络请求前立即停止；CLI 可用 `--request-limit` 调低或调整 |
| UTC 月带 key 上限 | 50,000 次尝试 | 到达后拒绝所有新的带 key 请求；只能修改源码才能提高仓库预算上限 |

月度账本写在 `data/cache/opendota_api_usage.json`。该目录已被 Git 忽略，账本只含月份、计数和
更新时间，不含 key、请求 URL 或响应。计数在请求发出前原子落盘，所以进程崩溃最多造成一次
保守的多计，不会漏计已经预留的请求。

更新账本时会短暂创建 `data/cache/opendota_api_usage.json.lock`。另一个同步进程遇到锁会立即
停止，避免并发运行绕过硬上限。正常退出会自动删除锁；如果进程被强制终止而留下旧锁，先确认
没有同步任务仍在运行，再手工删除该 `.lock` 文件。

## 死循环与重试

- 同一客户端进程内，如果相同资源路径和相同查询参数已经成功返回，再次请求会在联网前立即
  抛出重复请求熔断。正常重试不受影响，因为只有成功响应才登记请求签名。
- 网络错误以及 HTTP `500`、`502`、`503`、`504` 最多共尝试 4 次；三次等待依次为
  1、2、4 秒。
- HTTP `429` 同样最多共尝试 4 次，优先采用 `Retry-After`；服务端未提供时等待 61 秒。
- 其他非 2xx 状态不重试，立即以脱敏错误结束。
- 客户端仍保持至少 1.05 秒的请求间隔，约低于 60 次/分钟。Premium 页面显示的更高分钟额度
  不会被主动跑满；响应头和 `Retry-After` 始终优先。

`/proMatches` 分页另外保留游标单调递减检查。游标不前进时停止目录采集并生成阻断审计问题。

## Key 的放置和调用

真实 key 只放在仓库根目录的 `.env`：

```powershell
Copy-Item .env.example .env
# 在本机编辑 .env，只填写 OPENDOTA_API_KEY 的值。
```

调用时由 `uv` 注入环境：

```powershell
uv run --env-file .env ti data sync --as-of 2026-08-12T23:00:00Z --year 2026 --request-limit 500
```

不要把 key 写入命令行参数、PowerShell 历史、聊天、截图、源码或提交。程序写入原始抓取元数据
时只记录不带 `api_key` 的端点 URL；客户端异常只报告资源路径和 HTTP 状态，不包含最终请求
URL、查询参数、响应正文或底层异常链。项目也不应开启 `httpx` 请求级调试日志，因为第三方库
的原始 URL 日志可能包含查询参数。

## 建议运行额度

- 小组赛/胜负模型所需的年度目录与当前队伍摘要：先用 `--request-limit 500`。这不是预计会用完
  500 次，而是本次运行的止损线。
- 小范围验证：同时使用 `--max-matches 5 --request-limit 100`。
- Fantasy 全量历史：暂时不运行；恢复该工作时默认 5,000 次上限通常足够，并依靠 `match_id`
  断点续传。若估算超过 5,000，应拆成多个明确批次，而不是提高月度硬上限。

当前只为小组赛准备数据、不采 Fantasy 逐场详情时，使用：

```powershell
uv run --env-file .env ti data sync --as-of 2026-08-12T23:00:00Z --year 2026 --no-details --team-detail-limit 0 --request-limit 500
```

成功的 CLI 输出包含 `request_attempts` 和 `monthly_keyed_request_attempts`。前者是本进程实际发出
的尝试数；后者是该 UTC 月账本在本进程最后一次带 key 预留后的累计值。也可直接查看本地账本：

```powershell
Get-Content data/cache/opendota_api_usage.json
```

## 失败策略

预算耗尽、重复成功请求、账本损坏或账本锁冲突都属于安全停止：CLI 返回 `stopped` 和脱敏原因，
退出码为 2，不继续联网。账本损坏时不得删除后从零开始；应先从备份、OpenDota 用量页面和本月
运行记录核对已用量，再保守恢复计数。普通临时请求错误在完成有限重试后结束当前操作，不会进入
无限重试。
